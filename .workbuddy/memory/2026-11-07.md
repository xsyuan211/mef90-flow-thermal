# 2026-11-07 — DefMech AltMin 位移 SNES 非收敛：根因定位

## 任务
解决 Terzaghi 卡上 DefMech AltMin 位移 SNES 51/51 外层步报 -5 (SNES_DIVERGED_MAX_IT) 的非收敛缺陷。

## 决定性结论（CI #73, run 42372915986）
**根因 = 位移系统奇异（欠约束 / 刚体转动零空间），不是 Jacobian 数值 bug。**

铁证：
1. **FD（有限差分）Jacobian 同样失败**：V2（`-disp_snes_fd -disp_ksp_type gmres`, 1500s 跑满 51 步）报 `displacement SNES -5 count=52`，与解析 Jacobian 的 51×-5 几乎一致。FD J 由残差直接数值微分得到，数学上 = dR/du；FD 也失败 ⇒ 问题不在 J。
2. **矩阵确实奇异**：日志 `using diagonal shift to prevent zero pivot` + `tolerance for zero pivot 2.22045e-14` ⇒ 零主元 ⇒ 刚体零空间。
3. **残差首步 2.96e4→~10，卡在 5–10 振荡**：零空间方向的分量任何 Newton 步都无法消除。
4. **生产运行同样坏**：Gate 3.3(report-only) 报 `51 non-convergent DefMech SNES solves`。

## 物理根因
- 仅 `cs0020`(x=+5) 固定 u_x,u_y；`cs0010`(x=-5) 的 `displacementBC: 0,0,1` 在 2D(DIM=2) 下第三分量被忽略 → 实际未施加任何位移约束。
- 残留绕固定角点（x=+5）的刚体转动自由度；重力 (0,-9.81,0) 对 pin(x_cm=0 vs pin@x=+5) 产生净力矩，落在零空间方向 → 右端项不一致 → 残差降不到零 → -5。

## 已排除的解析 J 嫌疑（三重核对）
- HD split：`D2EED = d(DEED)/dε` 三阶自洽（SmoothPositiveSquare 族）确为正确切线；damage≈0 时系统退化为精确线弹性、J=HookesLaw。
- 残差/Jacobian 的 `.DotP.` 路径、积分阶、BC 施加(INSERT vs MatZeroRowsColumnsIS)、阻尼/内聚系数(本卡均为0)均一致。
- `MatSetNearNullSpace`（非 exact）仅服务 GAMG，不影响 KSP 求解；exact null space 被注释掉。即便开启 exact null space，因右端项零空间分量不一致也无法收敛 ⇒ 必须靠 BC 消除转动。

## 修复方向（deck 层面，非代码 J bug）
必须在 cs0010 补一个位移约束消除刚体转动。候选：固定 u_y(0,1,1 侧向约束/最近 oedometer)、固定 u_x(1,0,1 导向端)、两端全固定(1,1,1)。待用户确认后改 terzaghi1D.yaml 并触发 CI 验证（确认 displacement SNES -5 count=0）。
